# WebAPI — план реализации

**Цель** — расширить существующее API настройками напоминаний и сводки, обеспечить надёжную публикацию изменений для Worker.

**Основа** — [архитектура](README.md), [контракты RabbitMQ](04-rabbitmq.md), [существующие API и модели](../Auth/WebApplication1/).

## Настройки и публичные маршруты

| Метод и маршрут | Действие |
|---|---|
| `GET /api/habits/{id}/reminder` | Вернуть настройки напоминания владельцу привычки |
| `PUT /api/habits/{id}/reminder` | Заменить настройки напоминания и вернуть сохранённые значения |
| `GET /api/profile/summary-settings` | Вернуть настройки ежедневной сводки текущего пользователя |
| `PUT /api/profile/summary-settings` | Заменить настройки сводки и вернуть сохранённые значения |

У всех четырёх маршрутов ответ `200` с `{ "enabled": false, "localTime": "20:00" }` для напоминания или соответствующим временем сводки. `PUT` принимает оба поля. Время имеет формат `HH:mm`, диапазон `00:00`–`23:59`. Новые и существующие записи по умолчанию выключены, время напоминания `20:00`, сводки `21:00`. Настройки хранятся внутри документов привычки и пользователя. Календарные правила используют действующий часовой пояс аккаунта, по умолчанию `Asia/Yekaterinburg`.

Требовать JWT и валидный `sub`. Для чужой или отсутствующей привычки вернуть `404`, для изменения архивной привычки — `409`, для некорректного тела — `400`. Проверять владельца в фильтре MongoDB. Существующие маршруты и тела ответов сохраняются.

## Внутренние маршруты Worker

Доступ через `X-Worker-Key` с секретом `WorkerApi__SharedKey`, сравниваемым в постоянное время. Внешний ingress маршрутизирует `/api` и `/hubs`, а `/internal` доступен Worker через ClusterIP и сетевую политику. Ключ не записывается в логи.

| Метод и маршрут | Контракт |
|---|---|
| `GET /internal/v1/habit-schedules?after={id}&limit=100` | Страница полных снимков привычек по возрастанию ObjectId, включая выключенные и архивные, ответ `{ items, nextCursor }` |
| `GET /internal/v1/summary-schedules?after={id}&limit=100` | Страница настроек сводки с версией по ObjectId пользователя |
| `GET /internal/v1/users/{userId}/habits/{habitId}/reminder?date=YYYY-MM-DD` | `{ eligible, habitName, revision }`. Учитывает настройки, состояние, расписание, дату пользователя и отметку |
| `GET /internal/v1/users/{userId}/summary?date=YYYY-MM-DD` | `{ eligible, planned, completed, pending, revision }`. Считает активные привычки, запланированные на эту местную дату, через правила `HabitService` |

Снимки используют поля контрактов [RabbitMQ](04-rabbitmq.md) без транспортных метаданных. Для `limit` допустим диапазон `1..200`. Отсутствующая сущность возвращает `404`. Если проверяемая дата отличается от текущей местной даты, настройки выключены или привычка уже выполнена, архивирована либо вне расписания, вернуть `eligible: false`. Если все остальные условия выполнены, а срок в тот же день ещё не наступил, вернуть `eligible: false`, `reason: "notDueYet"` и `nextDueAtUtc`. WebAPI и Worker используют общий расчёт срока в UTC, включая переходы DST из [плана Worker](02-worker.md). Сводка допустима и при нуле запланированных привычек. Чтение привычек и отметок для одного вычисления проводить в согласованном снимке MongoDB.

## Шаги

- [ ] Создать `Auth/HabitTracker.Contracts` с записями событий v1 и закрепить общую версию MassTransit, совместимую с .NET 8. Подключить WebAPI как издателя `HabitChangedV1` и `SummarySettingsChangedV1`. Имена exchange, метаданные и параметры подключения взять из [спецификации RabbitMQ](04-rabbitmq.md). Для интеграционных тестов подготовить локальную топологию по [плану деплоя](05-deployment.md#сборка-и-локальный-запуск).
- [ ] Расширить `Habit`, `User`, DTO и контроллеры. Использовать текущий `Habit.Revision` для изменений привычки и отдельный `SummaryRevision` для настроек сводки. Инициализировать отсутствующие поля при чтении. Обновлять профиль и `lastLoginAt` отдельными `$set`, чтобы вход сохранял настройки пользователя.
- [ ] Расширить транзакции `HabitRepository` для create, edit, archive, reminder и изменений отметки. Транзакция меняет состояние, увеличивает версию при фактическом изменении и сохраняет полный снимок события в `outboxEvents`. Повтор установки уже существующей отметки, отмена отсутствующей и запись одинаковых настроек дают прежний успешный ответ без нового события. Аналогично сохранить настройки сводки вместе с `SummarySettingsChangedV1`.
- [ ] Добавить фоновую отправку outbox через MassTransit с подтверждением публикации. Реализовать захват с lease, повтор, сохранение идентификатора сообщения и очистку подтверждённых записей по [правилам outbox](04-rabbitmq.md#outbox). Использовать этот механизм и для издателя Worker. При недоступности RabbitMQ изменения сохраняются в MongoDB, очередь публикаций догоняет после восстановления.
- [ ] Добавить внутренние маршруты. Переиспользовать вычисления местной даты и версий расписания из `HabitService`. При проверке напоминания отличать изменение расписания от изменения отметки, используя текущий снимок и `revision`.
- [ ] Добавить глобальный `IExceptionHandler` с `ProblemDetails`. Сохранить действующие `code` и HTTP-статусы привычек. Возвращать `500` без деталей исключения и связывать ответ с журналом через `traceId`.
- [ ] Обновить документацию REST и MongoDB после реализации. Зафиксировать существующие индексы пользователей, привычек и отметок, добавить индекс ожидания публикации `outboxEvents(status, nextAttemptAt, _id)` и индекс восстановления истёкшего lease.

## Тесты по этапам

- [ ] **Контракты.** Тест сериализации проверяет обязательные поля трёх сообщений и передачу `MessageId`, `CorrelationId` и контекста трассировки.
- [ ] **Настройки и совместимость.** Модульные тесты проверяют значения по умолчанию и формат времени. HTTP-тесты проверяют `401` без JWT, `404` для чужой привычки, `409` для архива, `400` для неверного времени, повтор `PUT` и сохранение настроек после входа. Старые документы возвращают выключенные настройки с заданным временем.
- [ ] **Запись изменений и outbox.** Интеграционные тесты на replica set проверяют, что каждый фактический переход записывает состояние и событие с новой версией, а повтор команды сохраняет прежнюю версию и число событий. Ошибка записи события откатывает изменение данных.
- [ ] **Публикация.** Интеграционный тест с реальным RabbitMQ проверяет доставку обоих событий в `worker-habit-events-v1`, в том числе после запуска остановленного потребителя. При недоступности брокера API сохраняет изменение. После подтверждения публикации и сбоя до обновления outbox запись выходит из lease и публикуется с исходным `eventId`.
- [ ] **Внутренние маршруты.** HTTP-тесты проверяют ключ, пагинацию, местную дату, выключенные настройки, расписание, отметку, архив, перенос срока и сводку без привычек. Smoke-проверка ingress подтверждает, что публичный `/internal` не маршрутизируется в WebAPI.
- [ ] **Ошибки и индексы.** HTTP-тесты подтверждают действующие `code` и статусы ошибок, а при неожиданном исключении — `500` с `traceId` и без деталей. Интеграционный тест дважды запускает инициализацию и сверяет уникальность и состав индексов в MongoDB.
