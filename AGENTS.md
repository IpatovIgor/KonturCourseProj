# Правила изменения backend

Документы проекта: [архитектура](docs/architecture.md), [HTTP API](docs/api.md), [схема MongoDB](docs/database.md). При изменении публичного поведения обновляй контракт API и сценарии его проверки. При изменении данных обновляй схему, индексы и правила совместимости.

## Код

- Работай в существующем решении `Auth/WebApplication1.sln` на C# и .NET 8. Используй `MongoDB.Driver` и сохраняй разделение на `Controllers`, `Services`, `Data` и `Models`.
- Контроллеры отвечают за HTTP и DTO. Сервисы определяют правила расписания, выполнения, истории и статистики. Репозитории отвечают за запросы, обновления и индексы MongoDB. Используй отдельные DTO для запросов и ответов.
- Сохраняй маршруты, форматы ответов и JWT-контракт регистрации и входа. Сохраняй BCrypt и проверки подписи, издателя, аудитории и срока действия токена.
- Бери ID владельца из проверенного JWT. Передавай его в сервисы и репозитории. В запросах к привычкам и отметкам фильтруй по владельцу; ID привычки сам по себе не даёт доступа к данным.
- Используй асинхронные операции ввода и вывода. Передавай `CancellationToken` от новых HTTP-обработчиков до вызовов MongoDB.
- Используй `TimeProvider` для текущего времени. Храни моменты времени в UTC, а дни привычки — как календарные даты в часовом поясе пользователя.
- Меняй только поля, относящиеся к операции. Частичное обновление пользователя при входе должно менять только `lastLoginAt`, чтобы не затирать настройки профиля.

## Проверка изменений

- Из каталога `Auth` выполни `dotnet test WebApplication1.sln` перед сдачей изменений backend. Проверь существующие тесты авторизации и добавь проверки сценариев, на которые влияет изменение. Используй изолированную копию проекта для сборки, пока `bin` и `obj` отслеживаются Git.
- Для запросов MongoDB, индексов и конкурентных операций используй отдельную тестовую БД. Для доступа через JWT и форматов ответов используй тестовый HTTP-сервер ASP.NET Core.
- Перед сдачей проверь `git status --short` и `git diff --check`. Включай в изменения только исходники, тесты, настройки и документы по задаче. Сохраняй рабочие изменения других участников.
- Храни строку подключения с учётными данными и ключ JWT вне Git. Для локальной разработки используй User Secrets или переменные окружения. В документации используй вымышленные данные.
- Исключай результаты сборки `bin` и `obj` из новых коммитов. Очистку уже отслеживаемых результатов сборки выполняй отдельной задачей.
