# HTTP API трекера привычек

[Архитектура](architecture.md) · [Схема MongoDB](database.md)

В приложении доступны авторизация и маршруты `/api/habits`. Маршруты профиля и общей статистики описывают следующий этап первой версии.

## Соглашения

- У новых маршрутов заголовок `Authorization: Bearer <token>` обязателен. Владелец определяется по `sub` в JWT. JSON передаётся как `application/json`, имена полей в `camelCase`.
- ID в URL и ответах — 24 шестнадцатеричных символа MongoDB ObjectId. В ответах используются строчные символы. Неверный формат ID даёт `400`.
- Календарные даты передаются строго в формате `YYYY-MM-DD`. Метки времени привычек передаются в ISO 8601 в UTC с точностью до миллисекунд. Часовой пояс профиля — идентификатор IANA, например `Asia/Yekaterinburg`.
- Пустые списки возвращаются как `[]`. Ответы `204` не содержат тела.
- Общие коды новых маршрутов приведены ниже. Ошибки возвращаются как `application/problem+json`. Включить `status`, `title` и строковый `code`. При ошибке в поле можно вернуть `errors` с массивами сообщений по полям. Клиент опирается на `code`, поскольку текст может меняться.

| Статус | `code` | Причина |
|---|---|---|
| `400` | `validation_error` | Некорректные JSON, ID, дата, параметры или поля DTO |
| `400` | `invalid_completion_date` | Дата до начала, в будущем или вне расписания |
| `401` | `unauthenticated` | Нет действительного Bearer JWT или соответствующего аккаунта |
| `404` | `habit_not_found` | Привычка отсутствует или принадлежит другому пользователю |
| `409` | `habit_archived` | Редактирование привычки или изменение отметки в архиве |
| `409` | `timezone_locked` | Попытка изменить зафиксированный пояс |

Пример ошибки редактирования архива:

```json
{
  "status": 409,
  "title": "Привычка в архиве",
  "code": "habit_archived"
}
```

## Регистрация и вход

| Маршрут | JSON запроса | Ответы |
|---|---|---|
| `POST /api/auth/register` | `nickName`, `email`, `password` | `201` с `message`, при занятом email `400` с `message` |
| `POST /api/auth/login` | `email`, `password` | `200` с `token` и `email`, при неверных данных `401` с `message` |

Эти маршруты публичны. Фронтенд использует полученный `token` для защищённых запросов.

## Профиль

`GET /api/profile` возвращает `200` с объектом:

```json
{
  "id": "65aa00000000000000000001",
  "nickName": "Ира",
  "email": "ira@example.com",
  "timeZoneId": "Asia/Yekaterinburg",
  "canChangeTimeZone": true
}
```

`PUT /api/profile/timezone` принимает `{"timeZoneId":"Europe/Moscow"}` и возвращает `200` с обновлённым профилем в том же формате. Допускаются IANA-пояса, поддерживаемые хостом. Неизвестный пояс даёт `400`. До первой привычки можно менять пояс, затем изменение даёт `409`. Повтор запроса с тем же поясом возвращает текущий профиль. Пояс по умолчанию — `Asia/Yekaterinburg`.

## Привычки

| Маршрут | Успешный ответ | Особенности |
|---|---|---|
| `POST /api/habits` | `201`, объект привычки, `Location: /api/habits/{id}` | Стартует с местной даты создания |
| `GET /api/habits` | `200`, страница объектов привычек | Параметры `status`, `page` и `pageSize` |
| `GET /api/habits/{id}` | `200`, объект привычки | Доступен и для архива |
| `PUT /api/habits/{id}` | `200`, обновлённый объект привычки | Полное обновление редактируемых полей, архив даёт `409` |
| `DELETE /api/habits/{id}` | `204` | Архивирование. Повтор для архива того же владельца даёт `204` |

Создание и редактирование принимают одинаковое тело:

```json
{
  "name": "Зарядка",
  "description": "10 минут",
  "daysOfWeek": [1, 3, 5]
}
```

- `name` обязателен, 1–100 символов после обрезки пробелов.
- `description` необязателен, до 1000 символов после обрезки пробелов. Пропуск, `null` и пустая строка сохраняются как `null`. В `PUT` пропуск очищает описание.
- `daysOfWeek` обязателен. Это непустой массив уникальных целых чисел `1–7`, где `1` — понедельник. В ответах дни сортируются по возрастанию. Все семь дней означают ежедневную привычку.

Пример ответа после `PUT` с названием «Утренняя зарядка» и расписанием `[2, 4, 6]`. Название изменено сразу, новые дни вступят в силу завтра.

```json
{
  "id": "65aa00000000000000000011",
  "name": "Утренняя зарядка",
  "description": "10 минут",
  "daysOfWeek": [1, 3, 5],
  "nextSchedule": {
    "effectiveFrom": "2026-11-10",
    "daysOfWeek": [2, 4, 6]
  },
  "startDate": "2026-11-02",
  "createdAt": "2026-11-02T03:00:00Z",
  "updatedAt": "2026-11-09T03:10:00Z",
  "archivedAt": null,
  "archivedDate": null
}
```

`daysOfWeek` показывает действующую версию на сегодня, а для архива — на дату архивирования. `nextSchedule` равен `null`, если будущей версии нет или привычка в архиве. Для формы редактирования использовать `nextSchedule.daysOfWeek`, если есть будущая версия. Иначе использовать `daysOfWeek`. Это сохраняет запланированное изменение при правке названия. Повторный `PUT` в тот же день заменяет завтрашнюю версию, а передача текущих дней отменяет её.

`GET /api/habits?status=active&page=1&pageSize=20` возвращает объект с полями `items` (массив объектов привычек), `page`, `pageSize` и `totalCount`. `status` принимает `active` или `archived`, по умолчанию `active`. `page` начинается с 1, `pageSize` по умолчанию 20 и допускает 1–100. Сортировка по `createdAt` и `id`, оба по убыванию. `items` и `totalCount` вычисляются по одной выборке. Страница за пределами списка возвращает пустой `items` и общее число привычек по фильтру.

## Сегодня и отметки

`GET /api/habits/today` возвращает `200` с местной датой, поясом и активными привычками, запланированными на эту дату. В `items` лежат объекты привычек с добавленным булевым полем `completed`. Порядок совпадает с обычным списком, пагинации здесь нет.

```json
{
  "date": "2026-11-09",
  "timeZoneId": "Asia/Yekaterinburg",
  "items": [
    {
      "id": "65aa00000000000000000011",
      "name": "Зарядка",
      "description": "10 минут",
      "daysOfWeek": [1, 3, 5],
      "nextSchedule": null,
      "startDate": "2026-11-02",
      "createdAt": "2026-11-02T03:00:00Z",
      "updatedAt": "2026-11-02T03:00:00Z",
      "archivedAt": null,
      "archivedDate": null,
      "completed": false
    }
  ]
}
```

| Маршрут | Ответ | Действие |
|---|---|---|
| `PUT /api/habits/{id}/completions/{date}` | `204` | Создаёт отметку, если её ещё нет |
| `DELETE /api/habits/{id}/completions/{date}` | `204` | Удаляет отметку, если она есть |

Тела запроса нет. Оба маршрута принимают только запланированные даты от начала привычки до сегодняшнего дня включительно, с учётом версии расписания на дату. Архивные привычки доступны для чтения, их отметки нельзя менять. Например, `PUT /api/habits/65aa00000000000000000011/completions/2026-11-09` отмечает зарядку за понедельник.

## История

`GET /api/habits/{id}/history?from=2026-11-07&to=2026-11-09` возвращает `200`. Правила параметров `from` и `to` одинаковы для истории и статистики. Передавать обе границы или ни одной. По умолчанию период начинается 29 дней назад и заканчивается сегодня. Обе границы включены, диапазон составляет не более 366 дней, `to` не позже сегодня и не раньше `from`. Нарушение этих правил даёт `400`.

В ответе `from` и `to` — границы запроса. Дни отсортированы по возрастанию и ограничены датами жизни привычки, включая день архивирования. Если пересечения нет, `days` пустой.

```json
{
  "habitId": "65aa00000000000000000011",
  "from": "2026-11-07",
  "to": "2026-11-09",
  "days": [
    { "date": "2026-11-07", "status": "notScheduled" },
    { "date": "2026-11-08", "status": "notScheduled" },
    { "date": "2026-11-09", "status": "pending" }
  ]
}
```

| Статус дня | Условие |
|---|---|
| `completed` | День запланирован и есть отметка |
| `missed` | Запланированный день уже прошёл, отметки нет |
| `pending` | Сегодня запланировано, отметки пока нет |
| `notScheduled` | Дата входит в период действия привычки и не запланирована |

## Статистика

`GET /api/habits/{id}/statistics?from=2026-11-02&to=2026-11-09` возвращает `200` с показателями за период и сериями за всю историю:

```json
{
  "habitId": "65aa00000000000000000011",
  "from": "2026-11-02",
  "to": "2026-11-09",
  "plannedDays": 4,
  "completedDays": 2,
  "missedDays": 1,
  "pendingDays": 1,
  "completionRatePercent": 50,
  "currentStreak": 2,
  "longestStreak": 2
}
```

Для расписания пн/ср/пт это пример с пропуском 2 ноября, выполнением 4 и 6 ноября и ожиданием 9 ноября. `plannedDays` — сумма `completedDays`, `missedDays` и `pendingDays`. `completionRatePercent` равен `100 × completedDays / plannedDays` с округлением до двух знаков по правилу `MidpointRounding.AwayFromZero`. Если запланированных дней нет, процент равен `null`.

Серия — число последовательных выполненных запланированных дней. Дни вне расписания пропускаются. Пропущенный запланированный день завершает серию. Если сегодня ещё ожидает отметки, текущая серия считается по предыдущим запланированным дням. У архивной привычки текущая серия равна нулю. Лучшая серия сохраняет максимум по всей истории, с учётом исправлений до архивирования. При отсутствии выполнений обе серии равны нулю.

`GET /api/statistics?from=2026-11-02&to=2026-11-09` возвращает `200` с `from`, `to` и теми же пятью показателями периода. Поля `habitId`, `currentStreak` и `longestStreak` отсутствуют. Счётчики суммируются по всем привычкам пользователя, включая архивные в пределах срока их действия. Две привычки, запланированные на один день, дают две единицы в `plannedDays`. Процент вычисляется от суммарных счётчиков.
